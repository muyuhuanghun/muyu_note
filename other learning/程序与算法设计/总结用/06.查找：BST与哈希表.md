## 一、查找问题概述

```
💡 核心问题：给定一个关键字，在数据集合中找到对应的记录

两种主要方案：
  1. 基于比较的查找（BST、AVL、B树）→ O(log n)
  2. 基于计算的查找（哈希表）→ O(1) 平均

权衡：
  - BST：有序，支持范围查询，但最坏 O(n)
  - 哈希表：最快 O(1)，但不支持范围查询，需要处理冲突
```

## 二、二叉搜索树（BST）

### 1. 核心性质

```
🌟 BST 的定义：对于树中任意节点
  - 左子树所有节点的 key < 该节点的 key
  - 右子树所有节点的 key > 该节点的 key
  - 左右子树也分别是 BST

        8
       / \
      3   10
     / \    \
    1   6    14
       / \
      4   7

中序遍历：1 3 4 6 7 8 10 14 ← 自动有序！
```

### 2. 查找实现

```c
typedef struct bnode {
    int key;
    struct bnode *lchild;
    struct bnode *rchild;
} BSTNode, *BSTree;

BSTree searchBST(BSTree T, int key)
{
    if(T == NULL || T->key == key)  // 📌 找到或未找到
        return T;

    if(key < T->key)
        return searchBST(T->lchild, key);  // 小于根 → 查左子树
    else
        return searchBST(T->rchild, key);  // 大于根 → 查右子树
}
```

### 3. 查找过程图解

```
查找 key=6：

        8          6 < 8 → 走左
       / \
      3   10       6 > 3 → 走右
     / \    \
    1   6    14    6 == 6 → 找到！返回
       / \
      4   7

查找路径：8 → 3 → 6，比较次数 = 3 = 树的高度
```

### 4. 复杂度

| 情况 | 时间复杂度 | 说明 |
|:---|:---:|:---|
| 平均 | O(log n) | 平衡 BST，高度 ≈ log₂n |
| 最坏 | O(n) | 退化为链表（插入有序数据时） |

⚠️ BST 的致命问题：如果按升序插入数据，BST 会退化为链表。解决方案：AVL 树、红黑树等自平衡 BST。

## 三、哈希表

### 1. 核心思想

```
🌟 哈希表 = 关键字 → 直接算出存储位置

传统查找：逐个比较 → O(n)
BST 查找：二分比较 → O(log n)
哈希表：直接计算地址 → O(1)！

H(key) = 存储地址
例：H("ZhangSan") = sum(ASCII) % 61 = 37
    直接去 data[37] 找！
```

### 2. 数据结构定义

```c
#define TABLE_SIZE 61      // 📌 表长取素数（减少冲突）
#define STU_NUM 30         // 存储元素个数

typedef enum { EMPTY, OCCUPIED } Status;

typedef struct {
    char name[MAX_NAME_LEN];  // 姓名（关键字）
    Status status;            // 当前状态
} HashElem;

typedef struct {
    HashElem data[TABLE_SIZE];
    int count;                // 已存入的元素个数
} HashTable;
```

💡 **表长为什么取素数？** 如果表长是合数，某些关键字的哈希值会集中在某些位置，导致冲突增多。素数表长可以让分布更均匀。

### 3. 哈希函数 — 除留余数法

```c
int Hash(char *name)
{
    int sum = 0;
    while(*name)
    {
        sum += (int)(*name);  // 🌟 将每个字符的 ASCII 码累加
        name++;
    }
    return sum % TABLE_SIZE;  // 对表长取模
}
```

💡 除留余数法是最简单的哈希函数。缺点是：不同的关键字可能算出相同的地址（冲突）。比如 `"AB"` 和 `"BA"` 的 ASCII 和相同。

### 4. 冲突处理 — 线性探测再散列

```
🌟 线性探测：冲突时，依次向后查找空位

场景：H("ZhangSan") = 37，但 data[37] 已被占用
探测序列：37 → 38 → 39 → ... → 找到空位

类似排队：你的位置被占了，就往后挪一个
```

```c
int InsertHash(HashTable *HT, char *name)
{
    int addr = Hash(name);
    int start = addr;
    int len = 1;  // 查找长度

    // 🌟 线性探测：如果当前位置被占，向后移动
    while(HT->data[addr].status == OCCUPIED)
    {
        // 如果已存在相同姓名 → 插入失败
        if(strcmp(HT->data[addr].name, name) == 0)
        {
            printf("  [!] 姓名 \"%s\" 已存在，跳过\n", name);
            return -1;
        }

        addr = (addr + 1) % TABLE_SIZE;  // 📌 循环探测
        len++;

        // 探测一圈回到起点 → 表满
        if(addr == start)
        {
            printf("  [!] 哈希表已满，无法插入 \"%s\"\n", name);
            return -1;
        }
    }

    // 找到空位，插入
    strcpy(HT->data[addr].name, name);
    HT->data[addr].status = OCCUPIED;
    HT->count++;

    printf("  插入 \"%-10s\" -> Hash=%2d, 实际位置=%2d, 查找长度=%d\n",
           name, Hash(name), addr, len);
    return len;
}
```

### 5. 查找操作

```c
int SearchHash(HashTable HT, char *name)
{
    int addr = Hash(name);
    int start = addr;
    int len = 1;

    while(HT.data[addr].status == OCCUPIED)
    {
        if(strcmp(HT.data[addr].name, name) == 0)
        {
            printf("  查找 \"%-10s\" -> Hash=%2d, 实际位置=%2d, 查找长度=%d\n",
                   name, Hash(name), addr, len);
            return len;  // 📌 找到，返回查找长度
        }

        addr = (addr + 1) % TABLE_SIZE;
        len++;

        if(addr == start) break;  // 探测一圈
    }

    printf("  查找 \"%-10s\" -> 未找到\n", name);
    return -1;  // 未找到
}
```

### 6. 平均查找长度（ASL）

```c
// 🌟 ASL = 所有元素查找长度之和 / 元素个数
float CalcASL(HashTable HT)
{
    int totalLen = 0, found = 0;

    for(int i = 0; i < TABLE_SIZE; i++)
    {
        if(HT.data[i].status == OCCUPIED)
        {
            // 模拟查找该元素
            int addr = Hash(HT.data[i].name);
            int len = 1;
            while(strcmp(HT.data[addr].name, HT.data[i].name) != 0)
            {
                addr = (addr + 1) % TABLE_SIZE;
                len++;
            }
            totalLen += len;
            found++;
        }
    }

    if(found == 0) return 0.0f;
    return (float)totalLen / found;
}
```

📌 **ASL 的意义**：衡量哈希表查找效率的指标。理想情况下 ASL ≈ 1（一次就找到），如果 ASL > 2 说明冲突较多，需要调整表长或哈希函数。

## 四、冲突处理方法对比

| 方法 | 原理 | 优点 | 缺点 |
|:---|:---|:---|:---|
| **线性探测** | 冲突后向后逐个探测 | 实现简单 | 容易产生"聚集"现象 |
| **二次探测** | 冲突后按 1², -1², 2², -2²... 探测 | 减少聚集 | 可能找不到空位 |
| **链地址法** | 冲突元素存入同一链表 | 无聚集，删除简单 | 需要额外指针空间 |

本代码使用的是**线性探测**，是最简单但聚集风险最大的方法。
