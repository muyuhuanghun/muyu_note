# 五.性能优化指南

📌 性能优化是 llama.cpp 的高级玩法——通过编译优化、参数调优和硬件配置，榨干每一分性能。

# 一.CUDA 编译优化

## 1.启用 CUDA 加速

```bash
# 📌 从源码编译 llama.cpp（启用 CUDA）

# Step 1: 克隆仓库
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp

# Step 2: 安装 CUDA Toolkit
# 下载：https://developer.nvidia.com/cuda-downloads
# 确保 nvcc 在 PATH 中

# Step 3: 编译（启用 CUDA）
cmake -B build -DGGML_CUDA=ON
cmake --build build --config Release

# Step 4: 编译产物
# build/bin/llama-cli
# build/bin/llama-server
# build/bin/llama-quantize

# 💡 为什么从源码编译？
# - 启用 CUDA 加速（性能提升 2-5 倍）
# - 针对你的 GPU 架构优化
# - 支持最新特性
```

## 2.指定 GPU 架构

```bash
# 📌 针对特定 GPU 架构编译

# 查看你的 GPU 架构
nvidia-smi --query-gpu=compute_cap --format=csv

# 常见架构：
# RTX 30 系列 → Ampere (sm_86)
# RTX 40 系列 → Ada Lovelace (sm_89)
# A100        → Ampere (sm_80)

# 编译时指定架构
cmake -B build \
    -DGGML_CUDA=ON \
    -DCMAKE_CUDA_ARCHITECTURES="86"

# 🌟 好处：
# - 编译时间更短
# - 二进制文件更小
# - 性能略微提升
```

## 3.多 GPU 编译

```bash
# 📌 支持多 GPU 的编译配置

cmake -B build \
    -DGGML_CUDA=ON \
    -DCMAKE_CUDA_ARCHITECTURES="86;89"

# 多 GPU 使用
./llama-cli -m model.gguf -ngl 99 --tensor-split 0.5,0.5

# 💡 --tensor-split 用逗号分隔各 GPU 的负载比例
# 0.5,0.5 → 两张 GPU 各承担 50%
# 0.7,0.3 → 第一张 GPU 承担 70%
```

# 二.CPU/GPU 混合推理

## 1.显存不足时的策略

```bash
# 📌 混合推理：部分层在 GPU，部分在 CPU

# 场景：8GB 显存，7B 模型（需要 ~12GB）
# 解决：只加载部分层到 GPU

# 计算可加载层数：
# 可用显存 = 8GB - 2GB（预留） = 6GB
# 每层显存 ≈ 0.2GB（7B 模型）
# 可加载层数 = 6 / 0.2 = 30 层

./llama-cli -m model.gguf -ngl 30

# 🌟 效果：
# - 推理速度：比全 CPU 快 2-3 倍
# - 显存占用：~6GB
# - 质量损失：无
```

## 2.性能对比

```bash
# 📌 不同 -ngl 值的性能对比（7B Q4_K_M，8GB 显存）

# -ngl 0   → ~10 tokens/s（全 CPU）
# -ngl 20  → ~25 tokens/s（混合）
# -ngl 30  → ~35 tokens/s（混合，接近全 GPU）
# -ngl 99  → ~45 tokens/s（全 GPU，需要 12GB+ 显存）

# 💡 建议：
# 显存充足 → -ngl 99
# 显存紧张 → -ngl 30（平衡点）
# 显存极少 → -ngl 10-20
```

# 三.KV Cache 优化

## 1.KV Cache 显存占用

```bash
# 📌 KV Cache 是上下文长度的主要显存消耗

# 计算公式：
# KV Cache ≈ 2 * n_layers * n_heads * head_dim * context_len * 2 bytes

# 简化估算（7B 模型）：
# -c 2048  → ~0.5GB
# -c 4096  → ~1GB
# -c 8192  → ~2GB
# -c 16384 → ~4GB

# 💡 优化策略：
# 1. 使用 --flash-attn 降低 KV Cache 占用
# 2. 只在需要时增大 -c 值
# 3. 使用量化 KV Cache（实验性）
```

## 2.量化 KV Cache

```bash
# 📌 使用量化 KV Cache 节省显存

# 启用 Q8 量化 KV Cache
./llama-cli -m model.gguf -ngl 99 -c 8192 --cache-type-k q8_0 --cache-type-v q8_0

# 效果：
# - KV Cache 显存降低 50%
# - 质量损失极小
# - 支持更大的上下文长度

# ⚠️ 注意：
# 这是实验性功能，某些模型可能不稳定
```

# 四.批处理优化

## 1.Prompt Processing

```bash
# 📌 -b 参数控制 prompt 处理的批大小

# 默认值：512
./llama-cli -m model.gguf -b 512

# 增大批大小（更快处理长 prompt）
./llama-cli -m model.gguf -b 1024

# 减小批大小（节省显存）
./llama-cli -m model.gguf -b 256

# 🌟 建议：
# 显存充足 → -b 1024 或 2048
# 显存紧张 → -b 256 或 512
```

## 2.ubatch Size

```bash
# 📌 -ub 参数控制 micro-batch 大小

# 默认值：512
./llama-cli -m model.gguf -ub 512

# 减小 ubatch（降低显存峰值）
./llama-cli -m model.gguf -ub 256

# 💡 适用场景：
# 显存不足导致 OOM → 减小 -ub
# 需要更快的 prompt 处理 → 增大 -ub
```

# 五.多 GPU 配置

## 1.Tensor Split

```bash
# 📌 --tensor-split 分配模型到多张 GPU

# 两张 GPU 平均分配
./llama-cli -m model.gguf -ngl 99 --tensor-split 0.5,0.5

# 不均匀分配（第一张 GPU 更强）
./llama-cli -m model.gguf -ngl 99 --tensor-split 0.7,0.3

# 三张 GPU
./llama-cli -m model.gguf -ngl 99 --tensor-split 0.4,0.3,0.3

# 💡 查看 GPU 使用情况
nvidia-smi
```

## 2.多 GPU 性能

```bash
# 📌 多 GPU 性能注意事项

# 🌟 好处：
# - 可以加载更大的模型
# - 总显存增加

# ⚠️ 限制：
# - 需要 NVLink 或高速 PCIe 才能获得加速
# - 普通 PCIe 可能比单 GPU 更慢
# - 通信开销可能抵消并行收益

# 💡 建议：
# 有 NVLink → 使用 --tensor-split
# 普通 PCIe → 考虑只用一张 GPU
# 显存不够 → 使用 CPU/GPU 混合推理
```

# 六.性能测试与监控

## 1.基准测试

```bash
# 📌 使用 llama-bench 测试性能

# 测试生成速度
./llama-bench -m model.gguf -ngl 99 -t 8

# 输出示例：
# model                          | t/s    |
# Qwen2-7B-Q4_K_M.gguf          | 45.2   |

# 测试不同量化版本
./llama-bench -m model-Q4_K_M.gguf -m model-Q5_K_M.gguf -ngl 99

# 🌟 关键指标：
# t/s (tokens per second) → 生成速度
# 越高越好
```

## 2.实时监控

```bash
# 📌 监控 GPU 使用情况

# NVIDIA GPU
nvidia-smi -l 1    # 每秒刷新一次

# 查看显存占用
nvidia-smi --query-gpu=memory.used,memory.total --format=csv

# 查看 GPU 利用率
nvidia-smi --query-gpu=utilization.gpu --format=csv

# 💡 优化目标：
# GPU 利用率 > 80% → 充分利用
# 显存占用 < 90% → 预留缓冲
```
