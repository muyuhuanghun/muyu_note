# 四.核心参数详解与调优

📌 掌握 llama.cpp 的核心参数，才能真正发挥模型的性能。本章详解每个参数的作用和调优策略。

# 一.GPU 与显存参数

## 1.-ngl（GPU Offload Layers）

```bash
# 📌 -ngl 控制多少层模型加载到 GPU

# 语法：-ngl <层数>

# 示例：全部加载到 GPU
./llama-cli -m model.gguf -ngl 99

# 示例：只加载一半到 GPU（显存不足时）
./llama-cli -m model.gguf -ngl 20

# 🌟 建议值：
# -ngl 99   → 全部 GPU（显存充足时）
# -ngl 33   → 一半 GPU + 一半 CPU（混合推理）
# -ngl 0    → 全部 CPU（无 GPU 时）

# 💡 每层大约占用：
# 7B 模型：~200MB/层
# 13B 模型：~350MB/层
# 70B 模型：~800MB/层
```

## 2.显存计算公式

```bash
# 📌 快速计算需要的 -ngl 值

# 公式：可加载层数 = (可用显存 - 2GB) / 每层显存

# 示例：
# 显存 8GB，7B 模型（~200MB/层）
# 可加载层数 = (8 - 2) / 0.2 = 30 层
# 建议：-ngl 30

# 显存 6GB，7B 模型
# 可加载层数 = (6 - 2) / 0.2 = 20 层
# 建议：-ngl 20

# ⚠️ 预留 2GB 给 KV Cache 和系统开销
```

# 二.上下文长度参数

## 1.-c（Context Size）

```bash
# 📌 -c 设置上下文窗口大小

# 语法：-c <token 数>

# 示例：8K 上下文
./llama-cli -m model.gguf -ngl 99 -c 8192

# 示例：32K 长上下文
./llama-cli -m model.gguf -ngl 99 -c 32768

# 🌟 上下文与显存关系：
# -c 2048   → ~0.5GB KV Cache
# -c 4096   → ~1GB KV Cache
# -c 8192   → ~2GB KV Cache
# -c 16384  → ~4GB KV Cache
# -c 32768  → ~8GB KV Cache

# 💡 建议：
# 日常对话 → -c 4096 或 8192
# 长文档分析 → -c 16384 或 32768
# 代码生成 → -c 8192 足够
```

## 2.上下文长度与模型支持

```bash
# 📌 不同模型的原生上下文长度

# Qwen2.5    → 128K（支持超长）
# Llama 3.1  → 128K
# Gemma 2    → 8K
# Mistral    → 32K
# DeepSeek   → 128K

# ⚠️ 注意：
# -c 超过模型原生长度会导致质量下降
# 建议 -c 不超过模型原生上下文长度
```

# 三.CPU 线程参数

## 1.-t（Threads）

```bash
# 📌 -t 设置 CPU 线程数

# 语法：-t <线程数>

# 示例：使用 8 线程
./llama-cli -m model.gguf -t 8

# 🌟 最佳实践：
# 线程数 = CPU 核心数的一半

# 示例：
# 8 核 CPU → -t 4
# 16 核 CPU → -t 8
# 32 核 CPU → -t 16

# 💡 为什么是一半？
# - 留出核心给系统和其他进程
# - 避免线程竞争导致性能下降
# - GPU 推理时 CPU 负载较低
```

## 2.CPU 性能优化

```bash
# 📌 CPU 推理时的优化

# 设置 CPU 亲和性（Linux）
taskset -c 0-7 ./llama-cli -m model.gguf -t 8

# 禁用超线程（如果性能反而下降）
# 在 BIOS 中关闭超线程

# 💡 CPU 推理速度参考（7B Q4_K_M）：
# 8 核 → ~10 tokens/s
# 16 核 → ~18 tokens/s
# 32 核 → ~25 tokens/s
```

# 四.注意力机制参数

## 1.--flash-attn

```bash
# 📌 --flash-attn 启用 Flash Attention

# 语法：--flash-attn on

# 示例：
./llama-cli -m model.gguf -ngl 99 --flash-attn on

# 🌟 优势：
# - 显存占用降低 30-50%
# - 长上下文推理更快
# - 支持更大的 -c 值

# 💡 适用场景：
# - 长文档处理
# - 显存紧张时
# - 需要大上下文窗口

# ⚠️ 注意：
# 需要 Ampere 或更新架构的 GPU（RTX 30/40 系列）
# 部分老模型可能不支持
```

## 2.注意力机制对比

```bash
# 📌 不同注意力机制的性能对比

# 标准注意力：
# - 显存：高
# - 速度：慢
# - 兼容性：最好

# Flash Attention：
# - 显存：低（-30-50%）
# - 速度：快（+20-30%）
# - 兼容性：需要新 GPU

# 🌟 推荐：始终开启 --flash-attn（如果 GPU 支持）
```

# 五.生成参数调优

## 1.基础生成参数

```bash
# 📌 控制生成质量的核心参数

# Temperature（温度）
--temp 0.7      # 低温度，保守输出
--temp 1.0      # 标准温度
--temp 1.2      # 高温度，创造性输出

# Top-P（核采样）
--top-p 0.9     # 保守
--top-p 0.95    # 标准
--top-p 0.99    # 多样化

# Top-K
--top-k 40      # 标准
--top-k 20      # 保守
--top-k 100     # 多样化

# 🌟 推荐组合：
# 代码生成 → --temp 0.3 --top-p 0.9
# 日常对话 → --temp 0.7 --top-p 0.95
# 创意写作 → --temp 1.0 --top-p 0.95
```

## 2.重复惩罚

```bash
# 📌 防止模型重复输出

# Repeat Penalty（重复惩罚）
--repeat-penalty 1.1    # 轻度惩罚
--repeat-penalty 1.3    # 中度惩罚

# Repeat Last N（检查最近 N 个 token）
--repeat-last-n 64      # 检查最近 64 个 token
--repeat-last-n 128     # 检查最近 128 个 token

# Frequency Penalty（频率惩罚）
--frequency-penalty 0.5 # 降低高频词概率

# Presence Penalty（存在惩罚）
--presence-penalty 0.5  # 鼓励新话题

# 💡 如果模型开始重复：
# 1. 增加 --repeat-penalty 到 1.2-1.3
# 2. 增加 --repeat-last-n 到 128
```

## 3.参数调优实战

```bash
# 📌 不同场景的参数配置

# 场景一：代码生成（精确、保守）
./llama-cli -m model.gguf \

    -c 8192 \
    --temp 0.3 \
    --top-p 0.9 \
    --repeat-penalty 1.1

# 场景二：日常对话（平衡）

    -ngl 99 \

    --top-p 0.95 \
    --repeat-penalty 1.1

    -ngl 99 \
    -c 16384 \
    --temp 1.0 \
    --top-p 0.95 \
    --top-k 100 \
    --repeat-penalty 1.0

# 场景四：翻译任务（准确、一致）
./llama-cli -m model.gguf \
    -ngl 99 \
    -c 8192 \
    --temp 0.3 \
    --top-p 0.8 \
    --repeat-penalty 1.2
```
