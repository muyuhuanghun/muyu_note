# 三.模型量化与格式转换

📌 量化是 llama.cpp 的核心能力之一——通过降低模型精度来减少显存占用和提升推理速度，同时尽量保持模型效果。

# 一.量化类型详解

## 1.常见量化格式

```bash
# 📌 GGUF 量化类型对照表

# Q2_K    → 2-bit 量化，最小体积，质量损失明显
# Q3_K_S  → 3-bit 小型，体积小，质量一般
# Q3_K_M  → 3-bit 中型，平衡选择
# Q4_0    → 4-bit 基础量化
# Q4_K_S  → 4-bit 小型，推荐日常使用
# Q4_K_M  → 4-bit 中型，🌟 性价比最高
# Q5_K_S  → 5-bit 小型，质量较好
# Q5_K_M  → 5-bit 中型，质量优秀
# Q6_K    → 6-bit 接近原始质量
# Q8_0    → 8-bit 几乎无损
# F16     → 16-bit 半精度，无损
# F32     → 32-bit 全精度，最大体积

# 💡 选择建议：
# - 显存充足 → Q5_K_M 或 Q6_K
# - 日常使用 → Q4_K_M（最佳平衡点）
# - 显存紧张 → Q3_K_M 或 IQ4_NL
```

## 2.特殊量化格式

```bash
# 📌 IQ 量化（重要性量化）

# IQ4_NL  → 4-bit 非线性量化，比 Q4_K 更小但质量接近
# IQ4_XS  → 4-bit 超小型，极致压缩
# IQ3_XXS → 3-bit 超小型
# IQ2_XXS → 2-bit 超小型，质量损失大

# 🌟 IQ 量化特点：
# - 使用非线性映射，保留更多关键信息
# - 同等体积下质量优于传统量化
# - 推理速度略慢于传统量化
```

# 二.使用 llama-quantize 转换量化

## 1.基本用法

```bash
# 📌 量化转换命令

# 语法：llama-quantize <输入模型> <输出模型> <量化类型> [线程数]

# 示例：将 F16 模型量化为 Q4_K_M
./llama-quantize model-f16.gguf model-Q4_K_M.gguf Q4_K_M 8

# 示例：量化为 IQ4_NL
./llama-quantize model-f16.gguf model-IQ4_NL.gguf IQ4_NL 8

# 💡 线程数建议设为 CPU 核心数的一半
```

## 2.批量量化脚本

```bash
#!/bin/bash
# 📌 批量量化脚本：一次生成多种量化版本

INPUT_MODEL="model-f16.gguf"
OUTPUT_DIR="./quantized"
THREADS=8

mkdir -p $OUTPUT_DIR

# 定义要生成的量化类型
QUANTS=("Q3_K_M" "Q4_K_M" "Q5_K_M" "Q6_K" "IQ4_NL")

for QUANT in "${QUANTS[@]}"; do
    echo "🔄 正在量化: $QUANT"
    ./llama-quantize "$INPUT_MODEL" "$OUTPUT_DIR/model-${QUANT}.gguf" "$QUANT" $THREADS
done

echo "✅ 所有量化完成！"
```

# 三.从 HuggingFace 转换为 GGUF

## 1.转换 HuggingFace 模型

```bash
# 📌 将 HuggingFace 模型转换为 GGUF

# Step 1: 克隆转换工具
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp

# Step 2: 安装依赖
pip install -r requirements/requirements-convert_hf_to_gguf.txt

# Step 3: 转换模型（以 Qwen2 为例）
python convert_hf_to_gguf.py \
    /path/to/huggingface/model \
    --outfile model-f16.gguf \
    --outtype f16

# Step 4: 量化（可选）
./llama-quantize model-f16.gguf model-Q4_K_M.gguf Q4_K_M

# 💡 支持的模型格式：
# - HuggingFace Transformers
# - SafeTensors
# - PyTorch .bin
```

## 2.转换 SafeTensors 模型

```bash
# 📌 SafeTensors 转换

python convert_hf_to_gguf.py \
    /path/to/model.safetensors \
    --outfile model.gguf \
    --outtype q8_0

# 💡 SafeTensors 是更安全的模型格式，推荐使用
```

# 四.量化性能与质量对比

## 1.测试基准

```bash
# 📌 使用 llama-perplexity 测试量化质量

# 测试困惑度（越低越好）
./llama-perplexity \
    -m model-Q4_K_M.gguf \
    -f wiki.test.raw \
    -t 8

# 🌟 困惑度参考值：
# - 原始模型（F16）：基准值
# - Q8_0：几乎无损（+0.1-0.5%）
# - Q6_K：优秀（+0.5-1%）
# - Q5_K_M：良好（+1-2%）
# - Q4_K_M：可接受（+2-3%）← 推荐
# - Q3_K_M：一般（+3-5%）
# - Q2_K：较差（+5-10%）
```

## 2.速度测试

```bash
# 📌 测试推理速度

# 生成速度测试
./llama-bench \
    -m model-Q4_K_M.gguf \
    -t 8 \
    -ngl 99 \
    -n 128

# 输出示例：
# model                          | t/s    |
# Qwen2-7B-Q4_K_M.gguf          | 45.2   |
# Qwen2-7B-Q5_K_M.gguf          | 42.1   |
# Qwen2-7B-Q6_K.gguf            | 38.5   |

# 💡 速度影响因素：
# - 量化级别越低 → 速度越快
# - Q4 比 Q6 快 15-20%
# - IQ 量化比传统量化慢 5-10%
```

## 3.显存占用对照

```
# 📌 7B 模型显存占用参考

```

# 五.实战建议

```bash
# 📌 量化选择决策树

# 1. 显存 >= 8GB → 7B Q4_K_M 或 Q5_K_M
# 2. 显存 6-8GB → 7B Q3_K_M 或 IQ4_NL
# 3. 显存 < 6GB → 3B/1.5B Q4_K_M 或 7B Q2_K（质量差）

# ⚠️ 注意事项：
# - 量化不可逆，建议保留原始 F16 模型
# - 不同量化工具版本可能有差异
# - 某些模型对量化更敏感（如 Llama 3）
```
