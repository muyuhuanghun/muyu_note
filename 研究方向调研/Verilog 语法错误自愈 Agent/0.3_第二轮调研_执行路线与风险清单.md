## 2. 最小闭环系统路线

### 2.1 MVP 目标

先实现一个能跑通的最小系统：

```text
含 Bug 的 Verilog 源码
  → iverilog 编译（捕获 stderr）
  → Error Parser 解析（正则 + 错误分类）
  → Context Builder 组装 JSON prompt
  → LLM API 生成修复代码
  → Patch Applicator 替换源码
  → iverilog 重新编译
  → vvp 仿真验证（PASS/FAIL）
  → 循环直到通过或达到上限
```

### 2.2 MVP 不做什么

| 暂不做 | 原因 |
|:---|:---|
| SAEP（AST 联合图） | 先用正则验证闭环可行，再加 AST |
| LTBPR（23 类 Bug 分类） | 先用 10 种基础分类验证 |
| MRTM（MDP 记忆） | 先用简单 hash 去重验证 |
| 五层渐进检查 | 先用 iverilog + vvp 两层 |
| Verilator/Yosys/SpyGlass | 后续阶段加入 |
| 模型微调 | RTLHealer 定位为无需微调 |
| 仓库级修复 | 初期聚焦模块级 |
| 10 个以上 benchmark | 初期 6 个 Bug 类足够验证 |

## 5. EDA 桥接路线

### 5.1 iverilog 桥接（阶段 3 优先）

```python
# iverilog 命令行格式
iverilog -o output.vvp -g2012 -Wall design.v testbench.v

# 关键参数
# -o          输出 .vvp 文件
# -g2012      SystemVerilog 2012 支持
# -Wall       所有警告
# -t null     仅语法检查，不生成输出（快速验证模式）
```

### 5.2 Verilator lint 桥接

```python
# Verilator lint 命令行格式
verilator --lint-only -Wall design.v

# 输出格式: %Warning-CATEGORY: file.v:line: message
```

### 5.3 Yosys 综合桥接

```python
# Yosys 综合命令行格式
yosys -p "read_verilog design.v; synth -flatten; stat"

# 输出包含: 资源统计、警告（latch、组合环路等）
```

### 5.4 多层渐进检查流

```python
async def progressive_check(design_file, tb_file):
    """五层渐进检查，低层失败则跳过高层"""

    # Layer 1: 语法检查
    result = await compiler.compile([design_file, tb_file], "out.vvp")
    if not result.success:
        return {"layer": 1, "result": result}

    # Layer 2: Lint 检查
    lint_result = await verilator.lint(design_file)
    if lint_result.has_errors:
        return {"layer": 2, "result": lint_result}

    # Layer 3: 综合检查
    synth_result = await yosys.synth(design_file)
    if synth_result.has_warnings:
        return {"layer": 3, "result": synth_result}

    # Layer 5: 仿真验证
    sim_result = await simulator.simulate("out.vvp")
    return {"layer": 5, "result": sim_result}
```

## 6. 实验设计

### 6.1 对比方法

| 方法 | 描述 | 目的 |
|:---|:---|:---|
| Baseline (Zero-shot) | 直接让 LLM 一次生成，不反馈 | 验证闭环必要性 |
| RTLFixer-style | RAG + 正则解析 + 迭代修复 | 最直接的 baseline |
| MEIC-style | 迭代调试 + 无结构化反馈 | 对比结构化反馈价值 |
| AutoChip v2-style | EDA 反馈 + 无记忆 | 对比记忆机制价值 |
| **RTLHealer (Full)** | SAEP + LTBPR + MRTM + 五层检查 | 主方法 |
| RTLHealer w/o SAEP | 纯正则解析（消融） | 验证 SAEP 贡献 |
| RTLHealer w/o LTBPR | 统一权重（消融） | 验证 LTBPR 贡献 |
| RTLHealer w/o MRTM | 无记忆（消融） | 验证 MRTM 贡献 |

### 6.2 评估指标

| 指标 | 定义 | 用途 |
|:---|:---|:---|
| pass@1 | 单次生成直接通过率 | 基线质量 |
| pass@k (k=5,10) | k 次尝试中至少一次通过 | 闭环效果 |
| fix_rate | 编译通过率（含迭代） | 语法修复能力 |
| tb_pass_rate | testbench 通过率（含迭代） | 功能修复能力 |
| avg_iterations | 平均修复迭代次数 | 收敛效率 |
| oscillation_rate | 修复振荡比例（重复代码出现次数/总迭代） | MRTM 效果 |
| long_tail_fix_rate | 长尾 Bug（组合环路、CDC）的修复率 | LTBPR 效果 |
| token_cost | 总 LLM token 消耗 | 成本 |
| wall_clock_time | 总修复时间 | 工程效率 |

## 7. Prompt 设计

### 7.1 System Prompt

```text
You are an expert Verilog debugging agent. You receive a buggy Verilog module,
its testbench, and structured error reports from iverilog/Verilator/Yosys.

Your task is to return the COMPLETE corrected Verilog source code.

Rules:
- Do NOT change the module port interface.
- Do NOT change the functional intent.
- Prefer minimal changes: fix only what is broken.
- If a latch is inferred, add explicit default assignments.
- Do NOT repeat any fix strategy listed in iteration_history as already failed.

Output ONLY the code in a markdown code block with language tag 'verilog'.
After the code block, prefix a one-line summary with 'CHANGES:'.
```

## 8. 风险清单

| 风险 | 概率 | 影响 | 缓解措施 |
|:---|:---:|:---|:---|
| iverilog 安装/版本差异 | 低 | 编译错误格式不同 | 正则设计为宽匹配 + 版本检测 |
| LLM 返回不可解析代码 | 中 | 闭环中断 | 三级 fallback：精确匹配 → 通用代码块 → 纯代码检测 |
| LLM 修复振荡（反复相同修复） | 高 | 浪费迭代预算 | MRTM hash 去重 + 振荡检测 + 失败策略库 |
| 长尾 Bug 无法收敛 | 高 | CDC/组合环路修复失败 | 设置最大迭代次数 + 降级为"部分修复" |
| tree-sitter-verilog AST 解析不完整 | 中 | SAEP 降级为纯正则 | 先用正则兜底，AST 作为增强 |
| LLM API 成本高 | 中 | 实验不可持续 | 使用缓存、减少 prompt token、本地模型 |
| Benchmark 太小 | 中 | 泛化不足 | 第一批 6 个核心 Bug，扩展到 9 个 |
| 与 RTLFixer/MEIC novelty 重叠 | 中 | 投稿风险 | 强调 SAEP + LTBPR + MRTM 三重创新 |
| 五层检查工程量大 | 中 | 延期 | 先做 2 层（iverilog + vvp），后续扩展 |
| 真实 EDA 工具不可用 | 低 | 无法验证综合层 | iverilog + vvp 开源免费，Yosys 也是开源 |
