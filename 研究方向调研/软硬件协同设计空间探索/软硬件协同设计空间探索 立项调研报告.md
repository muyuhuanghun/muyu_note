## 一、方向选择理由与定位

### 1.1 方向定位

本方向是四个研究方向中 **难度最高、野心最大、学术影响力最广** 的一个。它不是单一工具的改进，而是提出一种 **全新的设计方法论**——将传统上割裂的"算法优化"和"硬件优化"统一到一个协同框架中。

**核心洞察**：在 FPGA 加速器设计中，算法层的选择（如用标准卷积还是深度可分离卷积）会从根本上改变硬件空间的结构。传统的单向优化（固定算法调硬件，或固定硬件调算法）必然陷入局部最优。

### 1.2 与其他方向的关系


## 二、Task 1：软硬件解耦优化的"局部最优解陷阱"论证

### 2.1 数学形式化

#### 2.1.1 设计空间定义

**软件参数空间** $W$：

$$W = W_{arch} \times W_{quant} \times W_{prune}$$

其中：
- $W_{arch} = \{\text{Conv}, \text{DWConv}, \text{GEMM}, \text{Attention}, \ldots\}$：架构选择空间
- $W_{quant} = \{b \in \mathbb{N} : 1 \leq b \leq 32\}$：量化位宽空间
- $W_{prune} = \{s \in [0,1] : \text{sparsity ratio}\}$：剪枝稀疏度空间

**硬件参数空间** $H$：

$$H = H_{pipe} \times H_{unroll} \times H_{partition} \times H_{resource}$$

其中：
- $H_{pipe} = \{II \in \mathbb{N} : 1 \leq II \leq 64\}$：Pipeline Initiation Interval
- $H_{unroll} = \{u \in \{1,2,4,8,16,32,64\}\}$：循环展开因子
- $H_{partition} = \{(d, f, t) : d \in \{0,1,2\}, f \in \{1,2,4,8,16\}, t \in \{\text{cyclic}, \text{block}, \text{complete}\}\}$：数组分区参数
- $H_{resource} = \{r \in \mathbb{R}^4 : 0 \leq r_i \leq R_{max}\}$：资源约束（LUT, FF, DSP, BRAM）

**联合设计空间**：

$$\mathcal{S} = W \times H$$

**设计空间规模估算**：

$$|\mathcal{S}| = |W_{arch}| \times |W_{quant}| \times |W_{prune}| \times |H_{pipe}| \times |H_{unroll}| \times |H_{partition}| \times |H_{resource}|$$

以一个典型的 3×3 卷积算子为例：

$$|\mathcal{S}| \approx 3 \times 8 \times 10 \times 8 \times 7 \times 15 \times 5 \approx 10^6 \text{ 配置}$$

而对于完整的神经网络（如 MobileNetV3，20+ 层），联合空间达到：

$$|\mathcal{S}_{network}| \approx (10^6)^{20} = 10^{120} \text{ 配置}$$

#### 2.1.2 多目标优化目标函数

定义优化目标函数 $F: W \times H \rightarrow \mathbb{R}^5$：

$$F(w, h) = \begin{pmatrix} \text{Accuracy}(w) \\ -\text{Latency}(w, h) \\ -\text{Power}(w, h) \\ -\text{LUT}(w, h) \\ -\text{DSP}(w, h) \end{pmatrix}$$

**帕累托最优定义**：配置 $(w^*, h^*)$ 是帕累托最优，当且仅当不存在 $(w', h')$ 使得：

$$\forall i: F_i(w', h') \geq F_i(w^*, h^*) \quad \land \quad \exists j: F_j(w', h') > F_j(w^*, h^*)$$

**帕累托前沿**：

$$\mathcal{P}^* = \{(w, h) \in \mathcal{S} : \nexists (w', h') \text{ s.t. } (w', h') \succ (w, h)\}$$

#### 2.1.3 全局最优与局部最优

**定理 1（局部最优陷阱）**：固定 $w = w_0$，仅在 $H$ 上搜索得到的帕累托前沿 $\mathcal{P}^*_{H|w_0}$ 是全局帕累托前沿 $\mathcal{P}^*_{W \times H}$ 的真子集，即：

$$\mathcal{P}^*_{H|w_0} \subset \mathcal{P}^*_{W \times H}$$

且存在 $(w^*, h^*) \in \mathcal{P}^*_{W \times H}$ 使得 $(w^*, h^*)$ 严格支配 $\mathcal{P}^*_{H|w_0}$ 中的某些点。

**证明思路**：

设 $w_0$ 为标准 3×3 卷积，$h_0^*$ 为在 $w_0$ 下的最优硬件配置。考虑 $w_1$ 为深度可分离卷积（Depthwise Separable Convolution），则：

- $\text{Accuracy}(w_1) \approx \text{Accuracy}(w_0) - \epsilon$，其中 $\epsilon < 1\%$（MobileNet 系列已验证）
- 计算量从 $C_{in} \times C_{out} \times K^2$ 降为 $C_{in} \times K^2 + C_{in} \times C_{out}$，约减少 $K^2 = 9$ 倍
- 因此存在 $h_1^*$ 使得 $\text{Latency}(w_1, h_1^*) \ll \text{Latency}(w_0, h_0^*)$

这意味着 $(w_1, h_1^*)$ 在 Latency-Accuracy 空间中支配 $(w_0, h_0^*)$，但固定 $w_0$ 的搜索永远找不到 $(w_1, h_1^*)$。$\blacksquare$

### 2.2 案例分析：从标准卷积到深度可分离卷积

#### 2.2.1 标准卷积的硬件空间

```
标准 3×3 卷积，C_in=64, C_out=128, H=W=56

计算量: 64 × 128 × 3 × 3 × 56 × 56 = 2.31 GMAC

HLS Pragma 优化空间:
┌─────────────────────────────────────────────────────────────┐
│ Pragma 配置              │ Latency  │ LUT    │ DSP   │ 评价 │
├──────────────────────────┼──────────┼────────┼───────┼──────┤
│ 无优化                   │ 1,254,400│ 2,400  │ 2     │ 基线 │
│ Pipeline II=1            │ 128      │ 8,200  │ 4     │ 好   │
│ Unroll factor=8          │ 156,800  │ 18,600 │ 16    │ 中   │
│ Pipeline + Unroll=8      │ 16       │ 72,400 │ 16    │ 爆炸 │
│ Pipeline + Unroll=16     │ 8        │ 145,600│ 32    │ OOM! │
└─────────────────────────────────────────────────────────────┘

瓶颈：64 个输入通道 × 3×3 卷积核 = 576 次乘法/输出像素
      → 要么串行（慢），要么并行（资源爆炸）
```

#### 2.2.2 深度可分离卷积的硬件空间颠覆

```
Depthwise Separable = Depthwise(3×3, C=64) + Pointwise(1×1, 64→128)

计算量: 64 × 3 × 3 × 56 × 56 + 64 × 128 × 56 × 56 = 0.32 GMAC
减少: 2.31 / 0.32 ≈ 7.2 倍

HLS Pragma 优化空间:
┌─────────────────────────────────────────────────────────────┐
│ Pragma 配置              │ Latency  │ LUT    │ DSP   │ 评价 │
├──────────────────────────┼──────────┼────────┼───────┼──────┤
│ 无优化                   │ 172,032  │ 1,800  │ 1     │ 基线 │
│ Pipeline II=1 (DW)       │ 64       │ 4,200  │ 2     │ 极好 │
│ Pipeline II=1 (PW)       │ 32       │ 6,800  │ 8     │ 极好 │
│ DW Unroll=64 + PW=128   │ 1        │ 52,400 │ 64    │ 可行！│ ← 标准卷积此配置 OOM
│ 全并行 + Pipeline        │ 1        │ 48,200 │ 64    │ 可行！│
└─────────────────────────────────────────────────────────────┘

关键变化：
- Depthwise 卷积：每个通道独立，天然可并行，无跨通道依赖
- Pointwise 卷积：1×1 卷积 = 矩阵乘法，标准并行模式
- 资源需求从 145,600 LUT 降到 52,400 LUT → 在 Zynq-7020 上可行！
```

#### 2.2.3 结论

固定算法调硬件的最优解是 $\text{Latency}=8, \text{LUT}=145,600$（超出器件容量，不可行）。

协同优化的最优解是 $\text{Latency}=1, \text{LUT}=48,200$（可行，且 Latency 更低）。

**帕累托前沿的维度和范围被软件层的选择根本性地改变了。**

### 3.3 搜索空间爆炸问题的解决策略

#### 策略 1：分层分解（Hierarchical Decomposition）

将 $|\mathcal{S}| = 10^{120}$ 的联合空间分解为可管理的子空间：

$$\mathcal{S} = \bigcup_{l=1}^{L} \mathcal{S}_l^{(W)} \times \mathcal{S}_l^{(H)}$$

其中 $l$ 为网络层级。每层独立优化，层间通过共享资源约束传递信息。

**优势**：将 $10^{120}$ 分解为 $20 \times 10^6 = 2 \times 10^7$（每层独立搜索）。

#### 策略 2：代理模型加速（Surrogate Model）

用 GNN 预测器替代真实 HLS 综合：

```
GNN 预测器: 0.01s/次 → 1000 次评估 = 10s
Vitis HLS:  2min/次  → 1000 次评估 = 33h

加速比: 12,000x
```

#### 策略 3：LLM 先验知识剪枝

LLM 利用领域知识跳过明显不合理的配置：

```python
# LLM 推理示例
"""
已知：MobileNetV3 的第 3 层是 Depthwise Conv, C=24, K=3
推理：
1. DW Conv 无跨通道依赖 → Unroll factor 可以设为 C=24
2. 24 × 9 = 216 次乘法 → Zynq-7020 的 220 DSP48 刚好够
3. 不需要 Array Partition（单端口 BRAM 够用）
→ 直接建议: Pipeline II=1, Unroll=24, 无 Partition
→ 跳过 10^4 个明显不优的配置
"""
```

#### 策略 4：帕累托档案引导搜索（Pareto Archive-Guided Search）

维护一个帕累托档案 $\mathcal{A}$，新配置只在支配 $\mathcal{A}$ 中某些点时才被评估：

$$\text{Evaluate}(w', h') \iff \exists (w, h) \in \mathcal{A} : (w', h') \text{ 可能支配 } (w, h)$$

### 3.4 与 cpp-to-verilog 和 GNN HLS 预测器的协同关系

| 协同维度 | 说明 |
|---------|------|
| 复用 cpp-to-verilog 的 Pragma Action Space | 硬件 Agent 的动作空间直接复用 DSP-aware Pragma 规则 |
| 复用 GNN 预测器作为快速判别器 | 硬件 Agent 每步评估从 2min 降到 0.01s |
| 复用 Feedback Extractor | 硬件 Agent 的反馈解析直接复用结构化反馈 Schema |
| 共享 DSP 基准算子 | 6 个 DSP kernel + 扩展的 Attention 算子 |

```
                    ┌─────────────────────────────────────────┐

                    └─────────────────────────────────────────┘

    ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
    │  INIT    │────→│  SW_ACT  │────→│  HW_ACT  │────→│  EVAL    │
    │ 初始化    │     │ 算法决策  │     │ 硬件决策  │     │ 评估反馈  │
    └──────────┘     └──────────┘     └──────────┘     └────┬─────┘
                                                            │

                         │                                  │

                    └────┬─────┘                       └────┬─────┘

```

### 4.3 状态详细定义

| 状态 | 触发条件 | 动作 | 输出 |
|------|---------|------|------|
| **INIT** | 系统启动 | 加载基准模型 + 初始 pragma 配置 | 初始 $(w_0, h_0)$ |
| **SW_ACT** | 从 INIT/UPDATE 进入 | 算法 Agent 分析当前 Pareto 档案，决定下一步软件调整 | JSON 协议消息 |
| **HW_ACT** | SW_ACT 完成 | 硬件 Agent 根据新的算法配置，搜索最优 pragma | JSON 协议消息 |
| **EVAL** | HW_ACT 完成 | GNN 预测器 / Vitis HLS 评估 $(w_i, h_i)$ | 评估指标 |
| **UPDATE** | EVAL 完成 | 更新帕累托档案，检查是否被支配 | 更新后的档案 |
| **CONVERGE** | UPDATE 完成 | 检查收敛条件 | 继续/终止 |
| **DONE** | 收敛或达到预算 | 输出帕累托前沿 | 最终结果 |

### 4.5 收敛条件

```python
def check_convergence(archive_history, current_iter, max_iter=50):
    """
    三种收敛条件：
    1. 达到最大迭代次数
    2. 帕累托档案连续 K 轮无更新
    3. 新增帕累托点的超体积增量 < 阈值
    """
    if current_iter >= max_iter:
        return True, "MAX_ITER"

    # 条件 2: 档案无更新
    no_update_rounds = 0
    for i in range(len(archive_history) - 1, 0, -1):
        if archive_history[i] == archive_history[i-1]:
            no_update_rounds += 1
        else:
            break
    if no_update_rounds >= 5:
        return True, "ARCHIVE_STABLE"

    # 条件 3: 超体积增量过小
    hv_gain = compute_hypervolume_gain(archive_history[-2], archive_history[-1])
    if hv_gain < 1e-4:
        return True, "HV_CONVERGED"

    return False, "CONTINUE"
```

## 五、Task 4：实验评估设计方案

### 5.1 基准测试集

#### 5.1.1 图像算子基准

| 算子 | 类型 | 参数规模 | 硬件特征 |
|------|------|---------|---------|
| **MobileNetV3 Block** | DW Conv + PW Conv | 24→24→144 | 内存带宽受限 |
| **ResNet BasicBlock** | 3×3 Conv ×2 + Skip | 64→64→256 | 计算密集 |
| **EfficientNet Block** | MBConv + SE | 32→160 | 混合受限 |
| **YOLOv5 Head** | 多尺度 Conv | 128→256 | 并行度需求高 |

#### 5.1.2 大模型算子基准（亮点）

| 算子 | 类型 | 参数规模 | 硬件特征 |
|------|------|---------|---------|
| **Mini-Attention** | QKV Projection + Softmax | d=64, h=4 | 矩阵乘 + 归一化 |
| **Mini-FFN** | 2 层 MLP + GELU | d=64, d_ff=256 | 大矩阵乘 |
| **Mini-MHA Block** | Attention + FFN + LayerNorm | d=128, h=8 | 完整 Transformer 块 |

📌 **引入 Mini-LLM 算子的意义**：大模型推理是 FPGA 加速的新兴场景，现有 HLS 优化文献几乎未覆盖 Attention 算子的软硬件协同优化。

### 5.2 Baseline 设计

| Baseline | 方法 | 说明 |
|----------|------|------|
| **B1: 固定算法 + AutoDSE** | 固定标准卷积，用 AutoDSE 搜硬件 | 单向硬件搜索 |
| **B2: 固定硬件 + NAS** | 固定 HLS 配置，用 DARTS 搜算法 | 单向算法搜索 |
| **B3: 交替搜索** | 轮流优化算法和硬件，无协同 | 简单交替，无通信 |
| **B4: 联合进化** | COEVO 风格的进化算法 | 无 LLM 推理能力 |
| **Ours: 双 Agent 协同** | 算法 Agent + 硬件 Agent + GNN 判别器 | 完整框架 |

### 5.3 评估指标

| 指标 | 公式 | 说明 |
|------|------|------|
| **帕累托超体积 (HV)** | $\text{HV}(\mathcal{P}) = \int_{\mathcal{P}} dx$ | 越大越好，综合评估前沿质量 |
| **帕累托前沿覆盖率** | $\frac{|\mathcal{P}_{ours}|}{|\mathcal{P}_{all}|}$ | 被本方法覆盖的非支配解比例 |
| **精度保持率** | $\frac{\text{Acc}(w_{opt})}{\text{Acc}(w_{baseline})}$ | 算法优化后的精度损失 |
| **加速比** | $\frac{\text{Latency}(w_0, h_0)}{\text{Latency}(w^*, h^*)}$ | 相对基线的延迟改善 |
| **资源效率** | $\frac{\text{Throughput}}{\text{LUT Usage}}$ | 每单位资源的吞吐量 |
| **搜索效率** | $\frac{\text{HV}(\mathcal{P})}{\text{Total Evaluations}}$ | 每次评估的帕累托贡献 |

### 5.4 实验矩阵

```
5 算子 × 5 Baselines × 3 随机种子 × 3 预算级别 = 225 次实验

预算级别:
- Tiny:   20 次 HLS 综合/算子
- Small:  50 次 HLS 综合/算子
- Medium: 200 次 HLS 综合/算子

使用 GNN 预测器时:
- GNN 预筛选: 1000 次 GNN 评估 (10s) + Top-20 送 HLS 验证
- 等效预算: 20 次 HLS 综合，但探索范围扩大 50 倍
```
