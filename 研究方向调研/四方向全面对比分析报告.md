## 一、四个方向概述

### 1.1 方向一：cpp-to-verilog（LLM 驱动 DSP-HLS 自适应调优）

| 项目 | 内容 |
|------|------|
| **核心思路** | 用 LLM Agent 闭环反馈机制自动优化 HLS C++ pragma（unroll, pipeline, array_partition），以 DSP 算子为目标，优化 Latency-Area Pareto 前沿 |
| **系统架构** | 六模块闭环：LLM Agent Controller + Code Parser + EDA Bridge + Metrics Extractor + Feedback Extractor + Pragma Action Space |
| **目标算子** | FIR, IIR, FFT butterfly, 2D Convolution, GEMM, CORDIC（6 个 DSP kernel） |
| **核心创新** | DSP-aware Pragma Action Space + 结构化反馈 Schema + 低预算 Pareto 优化协议 |
| **调研状态** | ✅ 两轮调研完成（含 GPT 5.5 改进意见），工程阶段待启动 |
| **投稿目标** | DAC / ICCAD / TCAD |

### 1.2 方向二：RTLHealer（Verilog 语法错误自愈 Agent）

| 项目 | 内容 |
|------|------|
| **核心思路** | 构建闭环 Agent，自动捕获 iverilog/Verilator 的 Error Log → 回传 LLM → 迭代修复至通过 Testbench |
| **系统架构** | 五模块闭环：Source Manager + Compiler Bridge (iverilog) + Error Parser & Feedback Extractor + Context Builder + LLM Agent Controller + Simulation Runner (vvp) |
| **核心创新** | SAEP（结构感知错误解析）+ LTBPR（长尾 Bug 惩罚奖励）+ MRTM（修复轨迹记忆） |
| **调研状态** | ✅ 四个 Task 全部完成（文献、报错特征、架构、Introduction） |
| **投稿目标** | DAC / ICCAD Student Research Contest |

### 1.3 方向三：GNN HLS 预测器（基于图神经网络的 HLS 性能与时序快速预测器）

| 项目 | 内容 |
|------|------|
| **核心思路** | 将 C++ DSP 源码 + HLS Pragma 编码为图结构，训练 GNN 在毫秒级预测 Latency / 资源占用，替代耗时的 Vitis HLS 综合 |
| **系统架构** | C++ → Clang AST → CDFG 图 → PIA-GAT 模型 → 多任务预测（Latency + 资源 + 时序可行性） |
| **核心创新** | Pragma 交互注意力层（PIA）+ 端到端图提取 Pipeline + 跨器件条件泛化 |
| **调研状态** | ✅ 调研报告完成（2026-06-15） |
| **投稿目标** | DAC / ICCAD / TCAD / FPGA |

### 1.4 方向四：软硬件协同设计空间探索

| 项目 | 内容 |
|------|------|
| **核心思路** | 双 Agent 协同框架——算法 Agent 负责模型剪枝/量化，硬件 Agent 负责 HLS pragma 调优，交替迭代寻找 PPA-Accuracy Pareto 前沿 |
| **系统架构** | 算法 Agent + 硬件 Agent + JSON 对唱协议 + 帕累托档案引导搜索 + GNN 判别器 |
| **核心创新** | 双 Agent 协同协议 + 帕累托引导搜索 + Mini-LLM 算子基准 + GNN 快速评估集成 |
| **调研状态** | ✅ 调研报告完成（2026-06-15） |
| **投稿目标** | ASPLOS / MICRO / ISCA / NeurIPS |

### 4.2 难度详细分析

#### cpp-to-verilog（难度：⭐⭐⭐ 中等）

- **理论要求**：需要理解 HLS 编译流程、pragma 语义、DSP 算法特性
- **工程要求**：Python + Tcl 脚本 + Vitis HLS 集成，工程量可控
- **数据集**：6 个 DSP kernel，每个 10-50 个综合点，数据量适中
- **最大挑战**：pragma 配置的合法性验证 + 综合报告的结构化解析

#### RTLHealer（难度：⭐⭐ 较低）

- **理论要求**：需要理解 Verilog 编译流程、常见错误模式
- **工程要求**：Python subprocess + iverilog 集成，工程量最小
- **数据集**：VerilogEval 已有 153 题，无需自建数据集
- **最大挑战**：长尾硬件 Bug 的 prompt 设计
- **优势**：已有完整调研报告 + Introduction 草稿，可直接进入工程阶段

#### GNN HLS 预测器（难度：⭐⭐⭐⭐ 较高）

- **理论要求**：需要深入理解 GNN 架构、图提取方法、多任务学习
- **工程要求**：Clang AST → CDFG 图提取器开发，工程量大
- **数据集**：需要 ~60K 标注样本，每个样本需要一次 HLS 综合（~2min/样本）
- **最大挑战**：数据集构建（83 天 CPU 时间）+ 图提取器开发 + Pragma 联合效应建模

#### 软硬件协同探索（难度：⭐⭐⭐⭐⭐ 最高）

- **理论要求**：多目标优化理论 + Agent 协同 + NAS + HLS 优化
- **工程要求**：双 Agent 框架 + 协议设计 + GNN 集成 + Mini-LLM 基准
- **数据集**：依赖 GNN 预测器的数据集 + 自身的 Pareto 档案
- **最大挑战**：双 Agent 收敛保证 + 搜索空间爆炸 + 论文跨领域覆盖
