# 自建 Memos 闪念同步方案

> 📌 本文档探讨自建 [usememos/memos](https://github.com/usememos/memos) 作为闪念笔记入口，通过 API 同步到 Obsidian 文件夹的技术方案。
> 核心定位：**Memos 负责快速捕获，Obsidian 负责深度整理**，两者通过同步桥接层连接。

---

## 🌟 方案概述

### 核心思路

```
手机/平板/网页 ──► Memos Server ──► 同步桥接脚本 ──► Obsidian/memos/ 文件夹
   (快速闪念)       (self-hosted)     (API 轮询)         (Markdown 文件)
                                           │
                                           ▼
                                     Obsidian 同步层
                                  (Git / LiveSync / 其他)
```

### 为什么需要 Memos

| 场景 | 纯 Obsidian | Obsidian + Memos |
|:---|:---|:---|
| 手机上快速记一句话 | ⚠️ 打开 App 慢，操作重 | ✅ 秒开，即记即走 |
| 碎片化想法捕获 | ❌ 流程太重，懒得记 | ✅ 降低记录摩擦 |
| 深度笔记整理 | ✅ Obsidian 核心优势 | ✅ 同步过来继续整理 |
| 多端同步 | 依赖同步方案 | Memos 自带 Web 端 |

### 与其他方案的关系

⚠️ **Memos 不是同步方案的替代品，而是内容入口的补充。**

```
┌─────────────────────────────────────────────────┐
│              完整笔记工作流                        │
│                                                   │
│  捕获层:  Memos (快速记录)                         │
│              │                                    │
│              ▼ 同步桥接                            │
│  存储层:  Obsidian Vault (深度整理)                │
│              │                                    │
│              ▼ 同步层                              │
│  分发层:  Git / LiveSync (多设备一致)              │
└─────────────────────────────────────────────────┘
```

## 🚀 部署步骤

### 第一步：部署 Memos 服务

#### 1.1 服务器要求

```bash
# 📌 最低配置（Memos 极其轻量）
CPU: 1 核
内存: 256 MB（Go 单二进制，占用极低）
硬盘: 5 GB（SQLite 存储，闪念笔记体积小）
系统: 任意支持 Docker 的 Linux

# 📌 网络要求
- 公网 IP 或域名
- 开放端口：5230（Memos 默认端口）
- 建议配置 HTTPS（同 LiveSync 方案，Nginx 反向代理）
```

#### 1.2 Docker 部署

```bash
# 创建工作目录
mkdir -p ~/memos && cd ~/memos

# 创建 docker-compose.yml
cat > docker-compose.yml << 'EOF'
version: '3.8'

services:
  memos:
    image: neosmemo/memos:stable
    container_name: memos
    restart: unless-stopped
    ports:
      - "127.0.0.1:5230:5230"   # 只监听本地，通过 Nginx 代理
    volumes:
      - ./data:/var/opt/memos   # 持久化数据
    environment:
      - TZ=Asia/Shanghai
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:5230/api/v1/status"]
      interval: 30s
      timeout: 10s
      retries: 3

# 📌 资源占用参考：
#   启动后内存 ~30MB，CPU 几乎为 0
#   和 CouchDB 可以部署在同一台服务器，互不影响
EOF

# 启动
docker-compose up -d

# 验证
curl http://localhost:5230/api/v1/status
# 预期输出: {"status":"OK",...}
```

#### 1.3 初始化设置

```
1. 浏览器访问 https://memos.yourdomain.com
2. 首次访问自动进入注册页面，创建管理员账号
3. 进入设置 → System → 基础配置：
   - 站点名称: 自定义
   - 时区: Asia/Shanghai
   - 注册策略: 禁止注册（单人使用）
4. 进入 My Account → Access Tokens → 创建 API Token
   📌 记录下这个 Token，同步脚本需要用到
```

### 第二步：Nginx 反向代理（HTTPS）

```nginx
# /etc/nginx/sites-available/memos
server {
    listen 80;
    server_name memos.yourdomain.com;

    location /.well-known/acme-challenge/ {
        root /var/www/html;
    }

    location / {
        return 301 https://$server_name$request_uri;
    }
}

server {
    listen 443 ssl http2;
    server_name memos.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/memos.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/memos.yourdomain.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;

    # 安全头
    add_header Strict-Transport-Security "max-age=63072000" always;
    add_header X-Frame-Options DENY always;
    add_header X-Content-Type-Options nosniff always;

    location / {
        proxy_pass http://127.0.0.1:5230;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket 支持（Memos 实时更新需要）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        client_max_body_size 50M;
    }
}
```

```bash
# 启用配置并申请证书
sudo ln -s /etc/nginx/sites-available/memos /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d memos.yourdomain.com
```

### 第三步：同步桥接脚本

这是方案的核心——将 Memos API 拉取的内容转换为 Obsidian Markdown 文件。

#### 3.1 同步脚本

```bash
#!/bin/bash
# 📌 memos-to-obsidian.sh
# 功能：轮询 Memos API，将新 memo 同步到 Obsidian 文件夹
# 用法：配合 cron 定时执行，或手动运行

set -euo pipefail

# ==========================================
# 配置区
# ==========================================
MEMOS_URL="https://memos.yourdomain.com"
MEMOS_TOKEN="your-api-token-here"                    # 📌 替换为你的 Access Token
OBSIDIAN_MEMOS_DIR="$HOME/Obsidian/muyu_note/memos"  # 📌 替换为你的 Obsidian vault 路径
STATE_FILE="$HOME/.memos-sync-state"                 # 记录上次同步时间戳
LOG_FILE="$HOME/.memos-sync.log"
ATTACHMENT_DIR="$OBSIDIAN_MEMOS_DIR/attachments"

# ==========================================
# 初始化
# ==========================================
mkdir -p "$OBSIDIAN_MEMOS_DIR" "$ATTACHMENT_DIR"
touch "$STATE_FILE"

# 上次同步的时间戳（秒），首次运行拉取全部
LAST_TS=$(cat "$STATE_FILE" 2>/dev/null || echo "0")

log() {
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] $*" >> "$LOG_FILE"
}

log "开始同步，上次同步时间戳: $LAST_TS"

# ==========================================
# 拉取 Memos
# ==========================================
# Memos API v1: 使用 filter 参数过滤创建时间
RESPONSE=$(curl -sf -H "Authorization: Bearer $MEMOS_TOKEN" \
    "$MEMOS_URL/api/v1/memos?pageSize=50" 2>/dev/null) || {
    log "❌ API 请求失败，请检查 MEMOS_URL 和 MEMOS_TOKEN"
    exit 1
}

# 检查是否有数据
MEMO_COUNT=$(echo "$RESPONSE" | jq '.memos | length')
if [ "$MEMO_COUNT" = "0" ] || [ "$MEMO_COUNT" = "null" ]; then
    log "✅ 没有新的 memo"
    exit 0
fi

log "📦 获取到 $MEMO_COUNT 条 memo"

# ==========================================
# 转换并写入文件
# ==========================================
NEWEST_TS=$LAST_TS

echo "$RESPONSE" | jq -c '.memos[]' | while read -r memo; do
    # 提取字段
    NAME=$(echo "$memo" | jq -r '.name')           # memos/123 格式
    MEMO_ID=$(echo "$NAME" | grep -oP '\d+$')
    CONTENT=$(echo "$memo" | jq -r '.content')
    CREATE_TIME=$(echo "$memo" | jq -r '.createTime')
    UPDATE_TIME=$(echo "$memo" | jq -r '.updateTime')
    VISIBILITY=$(echo "$memo" | jq -r '.visibility')

    # 跳过已同步的（基于时间戳）
    # Memos 的时间格式: 2026-06-24T14:32:00+08:00
    EPOCH=$(date -d "$CREATE_TIME" +%s 2>/dev/null || echo "0")
    if [ "$EPOCH" -le "$LAST_TS" ]; then
        continue
    fi

    # 解析日期和时间
    DATE=$(echo "$CREATE_TIME" | cut -d'T' -f1)
    TIME=$(echo "$CREATE_TIME" | cut -d'T' -f2 | cut -d'+' -f1 | cut -d'Z' -f1 | head -c 5)

    # 目标文件：按天聚合
    TARGET_FILE="$OBSIDIAN_MEMOS_DIR/$DATE.md"

    # 如果是当天第一条，创建文件头
    if [ ! -f "$TARGET_FILE" ]; then
        cat > "$TARGET_FILE" << HEADER
# 📝 闪念笔记 $DATE

> 从 Memos 自动同步 | [Memos Web 端]($MEMOS_URL)

---

HEADER
    fi

    # 提取标签（#tag 格式）
    TAGS=$(echo "$CONTENT" | grep -oP '#[\w一-鿿]+' | tr '\n' ' ' || true)

    # 写入 memo
    cat >> "$TARGET_FILE" << MEMO

## $TIME

$CONTENT

$([ -n "$TAGS" ] && echo "**标签**: $TAGS" || true)

> 🆔 Memos ID: $MEMO_ID | 🔒 $VISIBILITY

---
MEMO

    log "✅ 同步 memo #$MEMO_ID → $DATE.md"

    # 更新最新时间戳
    if [ "$EPOCH" -gt "$NEWEST_TS" ]; then
        NEWEST_TS=$EPOCH
    fi
done

# ==========================================
# 下载附件（图片等）
# ==========================================
echo "$RESPONSE" | jq -c '.memos[]' | while read -r memo; do
    # 提取 memo 中的图片 URL
    RESOURCE_LIST=$(echo "$memo" | jq -r '.resources[]?.name // empty' 2>/dev/null || true)
    if [ -n "$RESOURCE_LIST" ]; then
        echo "$RESOURCE_LIST" | while read -r resource; do
            RESOURCE_ID=$(echo "$resource" | grep -oP '\d+$')
            ATTACHMENT_URL="$MEMOS_URL/file/$resource"
            TARGET_PATH="$ATTACHMENT_DIR/memo-${RESOURCE_ID}.png"

            if [ ! -f "$TARGET_PATH" ]; then
                curl -sf -H "Authorization: Bearer $MEMOS_TOKEN" \
                    "$ATTACHMENT_URL" -o "$TARGET_PATH" 2>/dev/null && \
                    log "📎 下载附件: $RESOURCE_ID" || \
                    log "⚠️ 附件下载失败: $RESOURCE_ID"
            fi
        done
    fi
done

# ==========================================
# 更新状态
# ==========================================
if [ "$NEWEST_TS" -gt "$LAST_TS" ]; then
    echo "$NEWEST_TS" > "$STATE_FILE"
    log "📌 更新同步时间戳: $NEWEST_TS"
fi

log "✅ 同步完成"
```


## 🔧 高级配置

### 4.1 Webhook 实时推送（替代轮询）

如果 Memos 版本支持 Webhook，可以实现接近实时的同步：

```bash
#!/bin/bash
# 📌 memos-webhook-receiver.sh
# 配合 systemd 或 supervisor 运行一个轻量 HTTP 服务

# 使用 Python 实现一个简单的 webhook 接收器
cat > ~/memos-webhook.py << 'PYEOF'
#!/usr/bin/env python3
"""
Memos Webhook 接收器
收到 Memos 的创建/更新事件后，立即触发同步脚本
"""

import subprocess
import json
from http.server import HTTPServer, BaseHTTPRequestHandler

WEBHOOK_SECRET = "your-webhook-secret"  # 📌 设置一个密钥
SYNC_SCRIPT = "/home/user/memos-to-obsidian.sh"

class WebhookHandler(BaseHTTPRequestHandler):
    def do_POST(self):
        # 验证密钥
        auth = self.headers.get("Authorization", "")
        if auth != f"Bearer {WEBHOOK_SECRET}":
            self.send_response(401)
            self.end_headers()
            return

        # 读取 payload
        content_length = int(self.headers.get("Content-Length", 0))
        body = self.rfile.read(content_length)

        try:
            event = json.loads(body)
            event_type = event.get("type", "unknown")
            print(f"收到事件: {event_type}")

            # 触发同步
            subprocess.run([SYNC_SCRIPT], timeout=60)
            print("同步完成")

            self.send_response(200)
            self.send_header("Content-Type", "application/json")
            self.end_headers()
            self.wfile.write(b'{"status":"ok"}')

        except Exception as e:
            print(f"处理失败: {e}")
            self.send_response(500)
            self.end_headers()

    def log_message(self, format, *args):
        print(f"[Webhook] {args[0]}")

if __name__ == "__main__":
    server = HTTPServer(("127.0.0.1", 9090), WebhookHandler)
    print("Memos Webhook 接收器启动，监听 9090 端口")
    server.serve_forever()
PYEOF
```

```bash
# Nginx 中添加 webhook 路由
# 在 memos 的 Nginx 配置中增加：
location /webhook {
    proxy_pass http://127.0.0.1:9090;
    proxy_set_header Host $host;
}
```

### 4.2 双向同步（Obsidian → Memos）

如果需要在 Obsidian 中编辑后同步回 Memos：

```bash
#!/bin/bash
# 📌 obsidian-to-memos.sh
# 监控 Obsidian memos 文件夹的修改，更新到 Memos

MEMOS_URL="https://memos.yourdomain.com"
MEMOS_TOKEN="your-api-token"
WATCH_DIR="$HOME/Obsidian/muyu_note/memos"

# 使用 inotifywait 监控文件变化（需要安装 inotify-tools）
inotifywait -m -e modify --format '%w%f' "$WATCH_DIR" | while read -r file; do
    # 跳过非 .md 文件
    [[ "$file" != *.md ]] && continue

    # 提取文件名中的日期
    DATE=$(basename "$file" .md)

    # 解析文件中的 memo 条目并更新...
    # 📌 双向同步复杂度较高，建议先用单向同步验证可行性
    echo "检测到文件变化: $file"
done
```

⚠️ **双向同步复杂度高**，涉及冲突检测、ID 映射、内容合并等问题。建议初期只做单向同步（Memos → Obsidian），验证工作流后再考虑双向。

## ⚠️ 已知限制

### 1. 单向同步的局限

当前方案默认 **Memos → Obsidian 单向同步**：

- ✅ Memos 中创建的 memo 会同步到 Obsidian
- ❌ Obsidian 中编辑不会同步回 Memos
- ❌ Memos 中删除不会同步删除 Obsidian 文件

如果需要双向同步，复杂度显著上升（需要维护 ID 映射表、处理冲突）。

### 2. 时间戳精度问题

Memos API 返回的时间戳精度和本地 `date -d` 的解析可能存在差异，脚本中用 `EPOCH` 做去重，极端情况下可能漏同步或重复同步。

**缓解方案**：首次运行时设置 `STATE_FILE=0` 拉取全部历史，之后正常增量同步。

### 3. API 版本兼容

Memos 的 API 在大版本间有变化（v0.x → v1.x），脚本基于 v1 API 编写。如果使用旧版 Memos，需要调整 API 路径和字段名。

### 4. Markdown 格式差异

Memos 的 Markdown 和标准 Markdown 在标签处理上略有差异（Memos 用 `#tag` 而非 Obsidian 的 `[[tag]]`），同步脚本保留了原始格式，Obsidian 中仍可正常显示。
