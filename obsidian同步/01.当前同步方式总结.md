# 当前同步方式总结

> 📌 本文总结当前 Obsidian 仓库的同步方案，作为后续优化的基线参考。

---

## 🚀 当前方案：Git + GitHub

### 核心架构

```
┌─────────────┐     git push/pull     ┌─────────────┐
│  本地设备 A  │ ◄──────────────────► │   GitHub    │
│  (Windows)  │                       │  (远程仓库)  │
└─────────────┘                       └─────────────┘
       ▲                                     ▲
       │                                     │
       │ git push/pull                       │ git push/pull
       │                                     │
       ▼                                     ▼
┌─────────────┐                       ┌─────────────┐
│  本地设备 B  │ ◄──────────────────► │  其他设备    │
│  (如有)     │                       │  (如有)     │
└─────────────┘                       └─────────────┘
```

## 📊 方案优缺点分析

### ✅ 优点

| 维度 | 说明 |
|:---|:---|
| **版本控制** | 完整的 Git 历史记录，可回溯任意版本 |
| **冲突处理** | Git 原生冲突标记，手动解决可控 |
| **分支管理** | 支持多人协作，PR 审查流程 |
| **免费托管** | GitHub 免费提供仓库托管 |
| **离线可用** | 本地 commit 不依赖网络 |

### ❌ 缺点

| 维度 | 说明 |
|:---|:---|
| **同步延迟** | 需要手动 pull/push，非实时同步 |
| **操作繁琐** | 每次修改需 commit + push |
| **冲突风险** | 多设备同时编辑易产生冲突 |
| **学习成本** | 需要 Git 基础知识 |
| **移动端受限** | 移动端 Git 操作不便 |

## 🔄 当前工作流程

### 日常使用流程

```bash
# 📌 1. 开始工作前 — 拉取最新代码
git pull origin main

# 📌 2. 编辑笔记
# ... 在 Obsidian 中编辑 ...

# 📌 3. 提交更改
git add .
git commit -m "描述本次修改内容"

# 📌 4. 推送到远程
git push origin main
```

### 自动化配置（obsidian-git）

```yaml
# 插件设置（推测配置）
auto pull interval: 10 minutes  # 自动拉取间隔
auto commit: true               # 自动提交
auto commit message: "vault backup {{date}}"  # 自动提交信息
```

## ⚠️ 已知问题

### 1. 冲突处理

```bash
# 冲突示例
<<<<<<< HEAD
本地修改的内容
=======
远程修改的内容
>>>>>>> origin/main

# 解决方式：手动选择保留哪部分，删除冲突标记
```

### 2. 大文件限制

- GitHub 单文件限制 100MB
- 图片/附件较多时仓库体积增长快
- 已通过 `.gitignore` 排除大文件

### 3. 同步时机

- 非实时同步，存在时间差
- 忘记 push 可能导致数据丢失
- 多设备切换时需手动同步

## 💡 改进方向

基于当前方案的局限性，考虑以下改进：

1. **实时同步** — 替换为支持实时同步的方案
2. **自动化** — 减少手动操作
3. **冲突预防** — 自动合并或锁定机制
4. **移动端支持** — 更好的移动端体验
