# 一.GFW检测机制

## 1.三层检测模型

GFW不再仅依赖协议指纹识别，当前推测为**三层递进检测**：

| 层级 | 检测内容 | 技术手段 |
|------|----------|----------|
| 协议特征 | TLS握手指纹、加密套件、流量随机性 | 被动流量分析 |
| 行为侧写 | 连接时长、流量形态、使用时序 | 长期大数据积累评分 |
| 拓扑分析 | IP/ASN身份、源-目的关系、端口分布 | 元数据关联 |

单一协议伪装只能绕过第一层，无法应对后两层。

## 2.协议层：逻辑不自洽

即使协议外观完美，**身份与位置的合理性**才是关键：

- **脏IP问题**：搬瓦工、DMIT等热门VPS的ASN段，几乎没有外国人用来建正经站，GFW可以直接整段加高风险权重
- **SNI与落点的矛盾**：在搬瓦工IP上偷 `itunes.apple.com` 的SNI → 苹果会把服务部署在这种机房？
- **端口不合常理**：非443端口 + 大站SNI → 一眼假

> Xray核心开发者RPRX："这些热门翻墙机房能有几个IP是外国人拿来建正经站的？GFW即使直接全部一刀切损失都不大。"

## 3.行为层：流量形态出卖你

即使自建真实博客/网站，流量行为仍然异常：

| 正常网站访问 | 代理隧道行为 |
|-------------|-------------|
| 短连接为主 | 持续数小时的长连接 |
| 请求-响应交替 | 单向大下行流量 |
| 浏览型流量 | 流媒体+下载+IM混合节律 |
| 流量与内容成正比 | 看"博客"却跑了50G |

**关键矛盾**：谁会在个人博客上持续10小时跑50G流量？

## 4.拓扑层：元数据画像

剥离所有协议细节后，代理的本质极度稳定：

```
国内家宽IP ←→ 海外单一VPS IP（高频、长期、双向、下行占比高）
```

GFW只需维护一张元数据表即可聚类：
- 源IP（家宽/移动网络固定出口）
- 目的IP（海外固定节点）
- 连接频率与时间规律
- 上下行流量比率

**手机+电脑所有流量收敛进同一海外IP** → 这条通道在拓扑上天然像隧道。

# 二.应对策略

## 1.流量合理化

部署真实的高带宽业务来"解释"大流量：

- **私人影音**：Plex / Jellyfin / Emby 流媒体服务
- **私人网盘**：Nextcloud / Seafile
- **远程开发**：code-server / Jupyter

这些服务的流量特征（长连接、高下行）与代理隧道相似，能在行为侧写中被"合理化"。

## 2.REALITY偷证书的策略选择

| 策略 | 优点 | 缺点 |
|------|------|------|
| 偷大厂SNI（apple/microsoft） | 流量在统计上混入大厂 | 脏IP+大厂=逻辑不自洽 |
| 偷自己域名（自建伪装站） | 证书/IP/ASN完美闭环 | GFW不管你是不是真网盘，照封不误 |

**当前建议**：选一个与你VPS地理位置/ASN身份匹配的冷门站点做fallback，避免偷头部大厂。

## 3.屏蔽面板暴露面

X-UI等管理面板绝对不能直接暴露在公网：

```bash
# 阻断面板端口外网访问（假设面板在54321端口）
ufw deny 54321/tcp

# 通过SSH隧道本地访问
ssh -L 54321:localhost:54321 root@你的VPS_IP
```

SSH安全加固：

```bash
# 改非标端口 + 禁密码登录
# /etc/ssh/sshd_config
Port 2222                    # 改掉默认22
PasswordAuthentication no    # 仅允许密钥登录
```

## 4.定期更换IP

GFW的杀手锏是**长期数据积累评分**，直接釜底抽薪：

- 支持免费换IP的商家（如Vultr、Akile）→ 每1-2个月主动换一次IP
- 固定IP商家 → 套CDN隐藏真实IP，或备用多台低价VPS轮换
- 换IP = 清空GFW对这台机器的行为信用值

## 5.下一代传输协议

随着TLS单条TCP连接成为重点监控对象，逐步迁移到更隐蔽的传输层：

| 协议 | 特点 | 成熟度 |
|------|------|--------|
| xHTTP | 多路复用、模拟真实HTTP分块加载 | Xray主推，推荐关注 |
| xDNS | 通过DNS查询包建立隧道 | 极慢，仅末日备用 |
| xICMP | 通过Ping包传输数据 | 极慢，仅末日备用 |

xDNS/xICMP损耗极大（仅文字通讯级别），但可作为最后底牌。

# 三.专线机场的结构性脆弱

## 1.专线架构回顾

```
你的电脑 → 国内公网 → 机场国内入口 → 内网专线 → 境外出口 → 目标网站
                ↑                        ↑
           这一段不过GFW            这一段不过GFW
                ↑
        但这一段走在国内公网上！
```

跨境专线（IPLC/IEPL）确实不过GFW，但**你的家宽到机场国内入口这段是国内公网传输**。

## 2."省墙"的威胁模型

- **现状**：GFW主要部署在国际出口，国内流量互访基本不查
- **趋势**：各省反诈系统升级，"省级区域性防火墙/白名单"正在试点
- **原理**：省墙分析跨省流量 → 发现"持续向上海某数据中心发送大流量加密数据" → 符合VPN特征 → 直接在四川到上海的链路上阻断

省墙不需要判断你最终访问了什么，它只需要认定**四川→上海的这段国内流量"不像正常业务"**。

## 3.省墙一旦普及，专线机场同样被釜底抽薪

- 机场再快、专线再稳，国内入口被掐断 = 全站不可用
- 过去多家机场频繁通报（TCP阻断/连接重置）已是信号
- 专线解决的是跨境问题，堵的是跨境入口；**你根本到不了跨境入口**

# 四.总结

- GFW检测已从协议指纹 → 行为统计 + 拓扑分析，单一协议改进作用有限
- 核心矛盾不是"看起来像什么"，而是"行为像不像"
- 自建节点：定期换IP + 流量合理化 + 屏蔽暴露面 + 关注xHTTP
- 专线机场：省墙一旦普及，国内入口是致命弱点
- 不要把希望押在单一方案上，**分散风险、多层冗余**才是长期策略
