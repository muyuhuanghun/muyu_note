### 综合设计 I：单核 MCU - MSP430 上应用开发（基础夯实阶段）

本阶段表面上是简单的“电压温度采集+上位机绘制”，但它的底层逻辑是让你**跑通软件与硬件最原始的通信链路**，掌握裸机下的外设调度与低功耗控制。

#### 1. 需要学习与攻克的硬核知识

- **微控制器原理（寄存器级操作）**：掌握 MSP430 的时钟系统（BCS+）、低功耗模式（LPM0~LPM4）的切换机制。理解硬件中断服务程序（ISR）的编写规范以及中断向量表的概念。
    
- **模拟/数字转换（ADC10/ADC12 模块）**：深入理解采样保持时间、参考电压（Internal Vref 与 External Vref）、单通道单次/序列采样模式。如何计算采样频率以防止信号混叠。
    
- **串口通信协议（UART）**：掌握异步通信帧格式（起始位、数据位、校验位、停止位）。深入理解波特率产生器的分频系数配置（如基于特定晶振频率计算 `BRx`, `BRSx`, `BRFx` 寄存器的值）。
    
- **上位机异步数据流解析**：学习如何在 PC 端（Python `pyserial` 或 C++ QT `QSerialPort`）处理高频涌入的二进制/文本数据流。**必须设计严谨的数据帧协议**（如：`帧头 0xAA 55 + 数据长度 + 数据本体 + 校验和 + 帧尾 0x0D 0x0A`），避免串口断帧导致的解析崩溃。
    

#### 2. 需要做的工程与环境准备

- **IDE 环境**：安装 TI 的 Code Composer Studio (CCS) 或 IAR Embedded Workbench for MSP430。
    
- **上位机开发环境**：配置好 Python 环境（推荐用 `matplotlib` 或 `pyqtgraph` 跑动态曲线图），或者直接准备好 QT Creator（为大三的阶段三提前铺路）。

### 综合设计 II：单核 DSP 上的音频采集与处理（高带宽流处理阶段）

这个阶段是整门课程的关键质变点，它将你带入了实时流处理（Streaming）**与**实时操作系统（RTOS）的领域。

#### 1. 需要学习与攻克的硬核知识

- **实时操作系统（TI SYS/BIOS / TI-RTOS）**：理解硬件中断（Hwi）、软件中断（Swi）、任务（Task）以及后台线程（Idle）的优先级和抢占机制。熟练使用信号量（Semaphore）和事件（Event）同步线程。
    
- **音频编解码芯片控制（AIC3106）**：掌握 I2S 或者是 McASP（多通道音频串行端口）的时序。理解时钟树配置（BCLK、WCLK、MCLK 的关系）。
    
- **双缓冲区乒乓操作（Ping-Pong Buffering）机制**：这是保证音频不丢包、无断续的核心。你需要学会利用 EDMA（增强型直接内存访问）控制器：当 DMA 自动将硬件音频输入填满 Buffer A 时，触发中断，CPU 腾出手来去处理 Buffer B 里的上一帧音频；交替往复。
    
- **时域/频域数字信号处理算法**：
    
    - **FIR 滤波器**：理解卷积运算，掌握在定点/浮点 DSP 上使用循环展开优化乘累加（MAC）指令的方法。
        
    - **FFT 算法**：掌握基-2/基-4 蝶形运算的位反转（Bit-reversal）寻址和旋转因子（Twiddle Factors）的存储优化。
        

#### 2. 需要做的工程与环境准备

- **工具链**：CCS 升级并配置对应的 DSP 编译器支持（如 C6000 编译器系列）。
    
- **官方算法库安装**：在 CCS 中导入 TI 官方的 **DSPLIB**（针对 C674x 优化的数学库，里面有高度优化的 `DSPF_sp_fftSPxSP` 浮点 FFT 函数等）。

### 综合设计 III：基于 DM8168 的语音信号处理（异构多核终极黑客阶段）

这是难度最高、综合性最强的终极阶段。你需要扮演系统架构师的角色，解决**跨核心、跨操作系统**的通信与计算卸载问题。

#### 1. 需要学习与攻克的硬核知识

- **异构混合操作系统协作**：理解非对称多处理（AMP）模式。掌握主核（ARM）运行胖操作系统（Linux）负责业务调度与界面呈现，从核（DSP）运行轻量实时操作系统（SYS/BIOS）负责算力压榨的解耦设计。
    
- **多核进程间通信（IPC）与 RPE 框架**：深入理解共享内存（Shared Memory）、硬件邮箱中断（Mailbox）的底层逻辑。掌握 **RPE (Remote Processor Execute)** 引擎的客户端-服务器模型：ARM 发起 RPE 调用（如创建算法实例、传递控制数据指针），DSP 端的 RPE 服务器解析并调度对应的 XDAIS 算法组件进行本地执行。
    
- **高速缓存一致性（Cache Coherency）维护**：Linux 进程写完共享内存后，数据可能还在 ARM 的 L1/L2 Cache 里，没刷入物理 DDR；此时 DSP 去读会导致读到垃圾数据。**必须掌握何时手动执行 `Cache_wb`（写回）以及从核何时执行 `Cache_inv`（使无效）**。
    
- **Linux 音频架构（ALSA）与 QT 编程**：学习利用 Linux 的 ALSA 驱动捕获输入音频流（`/dev/snd/`），并利用 C++ 信号槽机制，在独立线程中将音频特征数据同步给主线程的 QT 绘图组件，实现动态波形谱展现。
    
- **高阶挑战算法：3D 空间音效增强**：理解 HRTF（头相关传输函数）三维声学空间建模。在 DSP 层面通过为左右耳分别施加不同的**双耳时间差（ITD）**、双耳声级差（IID）以及空间混响滤波器，把普通的单声道音频伪装成具备空间方位感的三维声场。
    

#### 2. 需要做的工程与环境准备

- **Linux 交叉编译链**：在你的开发机（如 Linux/WSL 环境）上配置面向 ARM Cortex-A8 的交叉编译器（如 `arm-linux-gnueabihf-gcc`）。
    
- **多核工具链组件（TI EZSDK / SysLink / IPC）**：确保拥有对应的多核工具链套件，并弄清 ARM 端 Linux 内核模块（如 `syslink.ko`）的加载流程。
