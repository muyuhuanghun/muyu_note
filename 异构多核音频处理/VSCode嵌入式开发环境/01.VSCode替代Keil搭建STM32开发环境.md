# 🚀 VSCode 替代 Keil5 搭建 STM32 开发环境（step-by-step）

> 📌 适用场景：自己玩 **STM32 / GD32 / 国民技术** 等 ARM Cortex-M 芯片时，用 VSCode + 开源工具链替代 Keil MDK。
> ⚠️ 课程内的 TI 平台（MSP430 → C674x DSP → DM8168）走 **Code Composer Studio (CCS)**，VSCode 替代不了——见文末「课程关联」。

# ==========================================
# 00. 总览：工具链全景（谁替代 Keil 的哪一块）
# ==========================================

# Keil MDK = 编辑器 + ARMCC编译器 + ULINK调试 + 器件包(DFP)，四合一商业 IDE
# VSCode 是"编辑器"，下面这套开源组合把它拆开替掉：

| 能力            | Keil 原生            | VSCode 替代方案                         |
| --------------- | -------------------- | --------------------------------------- |
| 编辑器/智能提示 | μVision 内置         | VSCode + C/C++ 插件（体验更好）         |
| 编译器          | ARMCC（商业，优化强）| GNU Arm Embedded Toolchain (arm-none-eabi-gcc) |
| 调试器后端      | ULINK/ST-Link 原生   | OpenOCD + J-Link / CMSIS-DAP / ST-Link  |
| 器件支持包 DFP  | 一键安装             | STM32 VS Code Extension 内置            |
| RTOS 感知调试   | RTX 原生             | ⚠️ 需手动配置                           |

# ==========================================
# 01. 工具清单与下载（💡 建议固定版本，避免玄学报错）
# ==========================================

# 🌟 核心四件套
# 1. VSCode          https://code.visualstudio.com/            (编辑器本体)
# 2. GNU Arm Embedded Toolchain  (编译器)
#                    https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads
#                    选 "AArch32 bare-metal target (arm-none-eabi)" 的 Windows 安装包
#                    版本建议：13.3.Rel1 (或 12.3.1，稳定老牌)
# 3. OpenOCD         https://openocd.org/ 或 https://github.com/openocd-org/openocd/releases
#                    版本建议：0.12.0（带 stlink / cmsis-dap 支持）
# 4. STM32CubeMX     https://www.st.com/en/development-tools/stm32cubemx.html
#                    (图形化配置时钟/引脚，生成工程骨架)

# 📌 调试硬件：ST-Link V2（最便宜，淘宝十几块）/ J-Link（贵但稳）/ CMSIS-DAP
#    课程实验板若自带 DAP 下载器，直接用，免驱更省心。

# ==========================================
# 02. 安装 GCC Arm 工具链 + 加入 PATH（🔧 Windows）
# ==========================================

# 🚀 安装后把 bin 目录加进系统 PATH，否则 VSCode 找不到编译器
#    默认安装路径示例：
#    C:/Program Files (x86)/Arm GNU Toolchain arm-none-eabi/13.3 rel1/bin

# 验证（Git Bash / PowerShell 均可）：
arm-none-eabi-gcc --version
# 期望输出：arm-none-eabi-gcc (Arm GNU Toolchain 13.3.Rel1) 13.3.1 ...

# 💡 没识别到？大概率 PATH 没生效——重开终端，或手动：
export PATH="$PATH:/c/Program Files (x86)/Arm GNU Toolchain arm-none-eabi/13.3 rel1/bin"

# ==========================================
# 03. 安装 OpenOCD + 加入 PATH（调试/烧录后端）
# ==========================================

# 解压到无空格路径，例如：
#    C:/tools/openocd-0.12.0/bin

# 验证：
openocd --version
# 期望输出：Open On-Chip Debugger 0.12.0 ...

# ⚠️ 坑：OpenOCD 靠 .cfg 文件认芯片。常见配置：
#    interface/stlink.cfg        # ST-Link 调试器
#    interface/cmsis-dap.cfg     # DAP 下载器
#    target/stm32f1x.cfg         # STM32F1 系列
#    target/stm32f4x.cfg         # STM32F4 系列
# 找不到芯片时，先确认 cfg 文件名对得上你的 MCU 型号。

# ==========================================
# 04. 安装 VSCode 插件（🌟 三件套）
# ==========================================

# 扩展市场搜并安装：
# 1. STM32 VS Code Extension   (ST 官方，id: stmicroelectronics.stm32-vscode-extension)
#    → 一键导入 CubeMX 工程、内置编译/烧录/调试，最接近 Keil 体验
# 2. C/C++                      (Microsoft, id: ms-vscode.cpptools)
#    → IntelliSense、跳转、重构
# 3. Cortex-Debug                (marus25, id: marus25.cortex-debug)
#    → 配合 OpenOCD 做断点/寄存器/内存实时调试

# 💡 可选增强：
#    - CMake Tools          (工程用 CMake 时)
#    - Embedded Tools       (微软官方，串口监视等)
#    - PlatformIO IDE       (跨厂商开箱即用，但偏黑盒，深入寄存器时不推荐)

# ==========================================
# 05. STM32CubeMX 生成工程骨架（🚀 启动工程）
# ==========================================

# 流程：New Project → 选型号(如 STM32F103C8T6) → 配时钟/引脚 → Project Manager 设置：
#   - Toolchain / IDE: 选 "Makefile" 或 "CMake"（官方扩展两者都支持）
#   - 勾选 "Generate Under Root"（方便 VSCode 打开）
# 点 GENERATE CODE → 得到 Core/、Drivers/、Makefile/CMakeLists.txt、.ioc

# 💡 生成后直接用 VSCode 打开工程根目录即可，STM32 扩展会自动识别 .ioc

# ==========================================
# 06. 编译配置：tasks.json（手写 Makefile 工程时用）
# ==========================================

# 官方 STM32 扩展自带 Build 按钮；若用裸 Makefile 工程，加 .vscode/tasks.json：
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "build",                         // 🌟 编译
      "type": "shell",
      "command": "make",
      "group": { "kind": "build", "isDefault": true },
      "problemMatcher": ["$gcc"]
    },
    {
      "label": "clean",                         // 清理
      "type": "shell",
      "command": "make clean"
    },
    {
      "label": "flash",                         // 🚀 烧录（OpenOCD 直烧 elf）
      "type": "shell",
      "command": "openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c \"program build/${workspaceFolderBasename}.elf verify reset exit\""
    }
  ]
}

# 快捷键 Ctrl+Shift+B 触发默认 build；命令面板选 flash 烧录。

# ==========================================
# 07. 调试配置：launch.json（Cortex-Debug + OpenOCD）
# ==========================================

# .vscode/launch.json：
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Cortex-Debug OpenOCD",           // 调试配置名
      "type": "cortex-debug",
      "request": "launch",
      "servertype": "openocd",
      "cwd": "${workspaceFolder}",
      "executable": "./build/${workspaceFolderBasename}.elf",  // 📌 必须是带调试信息的 .elf
      "device": "STM32F103C8",                  // 芯片型号（影响外设寄存器视图）
      "configFiles": [
        "interface/stlink.cfg",                 // 调试器
        "target/stm32f1x.cfg"                   // 目标 MCU
      ],
      "runToEntryPoint": "main",                // 启动后停在 main
      "svdFile": "./STM32F103xx.svd"            // 🌟 外设寄存器视图（ST 官网下，按型号选）
    }
  ]
}

# 💡 SVD 文件让调试时能看到 GPIO/USART/TIM 等外设寄存器实时值，体验直逼 Keil 的 Peripheral 窗口。

# ==========================================
# 08. 烧录与在线调试实战（🌟 核心流程）
# ==========================================

# 1) 接好 ST-Link：SWDIO / SWCLK / GND / 3.3V 四线连到板子（⚠️ 别接反 VCC）
# 2) VSCode 按 F5 → Cortex-Debug 启动 OpenOCD → 连上芯片 → 停在 main
# 3) 打断点、单步(F10/F11)、看变量/调用栈/内存
# 4) 外设视图里点开 GPIOA → 翻转 ODR 位 → 看 LED 实际亮灭（硬件闭环验证）
# 5) 改代码 → Ctrl+Shift+B 重新 build → F5 重新下板

# 等价于 Keil 的：Build(编译) + Download(烧录) + Debug(调试) 三件套，全部 cover。

# ==========================================
# 09. ⚠️ 常见坑（踩过才记得住）
# ==========================================

# 📌 坑1：ARMCC vs GCC 二进制不一致
#    Keil 的 ARMCC 优化更强，少数老例程强依赖 ARMCC 语法。
#    GCC 完全免费无 32KB 限制，但编译产物可能与 Keil 不完全一致——工程级无碍。

# 📌 坑2：ST-Link 驱动 / "target not halted"
#    先装 STSW-LINK009 驱动；OpenOCD 报 target not halted 多半是 cfg 型号不对或板子没上电。

# 📌 坑3：OpenOCD 找不到 .cfg
#    configFiles 里写的是 OpenOCD 自带的相对路径，不要写绝对路径；
#    自定义板子可放工程根目录 ./my_board.cfg 再引用。

# 📌 坑4：中文路径 / 空格路径
#    GCC + OpenOCD 对中文/空格路径过敏，工程放纯英文无空格目录（如 C:/ws/stm32_led）。

# 📌 坑5：RTOS 感知调试
#    Keil 对 RTX 原生感知；FreeRTOS/SYS-BIOS 在 VSCode 需额外配
#    FreeRTOS 可用 cortex-debug 的 "freertos" 支持（见插件文档）。
